# Changelog

## Unreleased

Fixes from the November 2026 review of the whole project. Each has a test that showed the fault first.

- A plain copy that ended early is a failed run. When robocopy was closed half-way (its log has no totals), the run used to be reported as a success and the date of the last complete backup moved on. An exit code of 8 or more can no longer end as "nothing left uncopied" either.
- Each selected folder has its own copy log. `a\b` and `a_b` used to share one, so a failure in the first was hidden by the second.
- *Keep deleted* never deletes the recovery folder it made in the same run (it could, after a clock or time-zone change), counts the files it really moved, and goes on past a file it cannot move, naming it.
- A folder that became a file (or the reverse) no longer blocks the plain copy: the old item is moved to the run's dated recovery folder and the new one is copied in the same run. Nothing is deleted; the recovery folders follow *Keep deleted* as before, and with *Keep deleted* at 0 none is ever removed. A selected folder that is left out because its name is on the always-skipped list (for example `venv`) is named in the run's result, and a folder selected on its own is copied and checked whatever its name.
- The content check no longer reports names ending in a dot as missing. Folder names are compared exactly, so a name of invisible characters no longer stops a run. `Exclude` paths with wildcards (`*/dist`) work in the plain copy as they do for versions.
- Plain copy and `Set-BackupDestination.ps1` refuse a backup drive that is a virtual disk stored on the source's physical disk; before, only the other direction was checked.
- A backup that could not read every file is saved as a partial version: labelled in the history, left alone by *Keep versions*, and never the reason a complete version is deleted. Partial versions made before this change cannot be told apart.
- *Keep versions* cleans up only this computer's versions, deletes in batches (more than about 500 at once used to fail), and refuses to work without the ID of the version just made.
- Restore below protected folders (for example `C:\Users`) completes with a warning and says plainly that the content was not verified, instead of reporting a failure.
- An interrupted password change can be resumed after the backup drive got another letter. Saving a recovery key first checks that the stored password opens the repository. A lock left in the repository by a backup that was stopped, crashed or ran out of memory is removed automatically, but only when it was made on this computer and the process that made it has ended; the step is then tried once more and the result says so (`LockReleased`). A lock of another computer, of a backup still running, or one that cannot be judged is never removed; the message says which.
- Versioned runs show how much they stored and read (`BackupSummary` in `result.json`); the columns used to stay empty. A run whose tool ended with a failing exit code, or whose result cannot be read in full, is never recorded as a success, and totals that were not read are recorded as unknown, not as 0.
- The window says so when `profiles.local.json` is damaged (it used to not open at all) and leaves the file untouched; a damaged look file falls back to the default look.
- The window keeps itself current: ages, colours and "Connected" refresh when it is activated and once a minute, without losing the selection or unsaved folder choices. It no longer asks Windows for all volumes every second during a run.
- A backup cannot start on a drive that is being checked or speed-tested, also after waiting for AI sessions; the buttons follow.
- Adding a removed folder again says that its earlier settings and folders were restored and the new choice was not applied.
- *Stop* and closing the window during a run are recorded as "Stopped by you", not as a tool failure. Elapsed time is rounded down, speed uses exact seconds, and a history line with an unreadable time no longer breaks the window. Times written in UTC are aged correctly. A network folder as a source is refused in plain words.
- Load levels never shrink from Light to Maximum on computers with two or three processor threads.
- Look: the check covers every text the window draws, large status text included, and the built-in themes and the default Custom colours pass it. No explanation is cut off at the smallest size.
- Drive check: a controller reset counts only when it comes from the drive's own kind of connection (an internal drive's reset was held against a USB drive). A new full scan no longer erases the bad areas the last one found. "No problems" is not shown for parts that could not be checked. A failed self-test of any kind is a problem; a place that reads only at the second try is a warning; *Stop* takes effect within one 4 MiB read; any `smartctl` path is checksum-checked; a damaged saved position is set aside instead of stopping every scan; sizes are labelled GiB/MiB.
- Privacy check: reads UTF-16 and text inside binary files, catches `/c/…` and `/mnt/c/…` profile paths and addresses that merely contain "noreply", and in CI checks every pushed commit, not only the newest.
- The report generator handles two processors, an unmeasured USB link and `<!--<script` in notes.
- **Repair differing files** on the overview: copies again only the files the last content check found different, unreadable or missing. Each new copy is compared with the source first; only then the old version is moved to a dated recovery folder and the new one takes its place. It deletes nothing and does not count as a backup (`Invoke-FastMirror.ps1 -Repair`).
- The run's result warns about files skipped through their short Windows name (an `Exclude` name such as `*.htm` also skips `page.html`) and about names in one folder that differ only by upper and lower case, which the copy cannot both keep.
- Starting DevDriveBackup twice brings the open window to the front instead of opening a second one that could overwrite the first one's settings.
- A damaged settings file can be restored from the last good copy (`profiles.lastgood.local.json`, kept at every save). The damaged file is always kept beside it under a dated name; settings are never reset silently.
- The overview and the drive list warn when the latest run of a source failed or was stopped, beside the age of the last complete backup, which is unchanged. A content check that found a problem shows as a milder line until a clean check, a repair or a comparing backup.
- Buttons that are off say why. With several sources and none selected, the links ask for a source instead of acting on the first. *Check backup content* asks one question with named answers.
- Detailed step logs are deleted after 30 days; the run history and the run folders' summaries are kept.
- A custom memory limit above half of the computer's memory gets a warning; it is not changed. More than 64 files at once is no longer refused by the plain copy.
- Privacy check: a private value of 8 characters or more is also found inside a longer word.
- Drive check: the drive database beside `smartctl` must be the official installer's and is kept open while the check runs, and a library file placed beside the tool stops it from running.
- Fixed on the way: a file-and-folder swap or a deleted file was sometimes missed when robocopy wrote two records as one; the restore and key windows open when the tool folder's name has a space.
- Tests: `Test-BackupMirror.ps1`, `Test-BackupVersionsRules.ps1`, `Test-BackupVersions.ps1`, `Test-BackupData.ps1`, `Test-BackupWindow.ps1`, `Test-BackupTools.ps1`, `Test-BackupToolsReport.py` and `Test-PrivacyGuardRules.ps1` are new, need no second drive and run on every push. A test helper that passed when nothing failed is fixed.

- The privacy check no longer checks the email addresses on the last commit in CI. Merges made on GitHub, and the test merge GitHub builds for a pull request, carry the account's own email, so every pull request failed. Commit names and messages, every tracked file, and the identity of local commits (pre-commit hook) are still checked.
- Plain copy never copies DevDriveBackup's password and recovery key folders or key files, also when one of them is itself a selected folder or file. robocopy skips folders only below the one it copies, so such a selection used to be copied as it was, readable recovery keys included. The run now names it as not copied, and names an older copy of a private folder still in the plain copy so it can be deleted.
- A new source never gets the plain copy or versions folder of a removed source of the same drive. Removed sources keep their folders on the drive, but only connected drives were checked for names in use, so a folder with the same name added while the drive was unplugged wrote into the old copy, and with *Keep deleted* moved the old source's other files aside. A removed folder added again gets its own folders back, unless another source now uses its repository; then it starts with new ones.
- Before a drive check asks for administrator rights, the window checks whether other accounts can change what it runs (its scripts, `smartctl` and its folder) or rename a folder above them, names those accounts and asks first; a junction or link on the way counts too. The check runs the bundled `smartctl.exe` only when its SHA-256 matches the official 7.5 build and keeps it open, readable only, while it runs; **Install health tool** keeps the installer open in the same way from its checksum check until it has run.
- The drive check judges the newest short and the newest long self-test that passed or failed each on its own; a newer interrupted one is only mentioned. Before, only the newest entry counted, so the short test of a quick check that passed hid a long self-test that had failed.
- After deleting old versions, *Keep versions* frees their space in a separate step and checks the repository again outside the clean-up's own error handling: if that check fails, the backup is reported as failed, because the repository may be damaged. Before, it was only a note on a successful backup. The note now also says how many versions were deleted when freeing their space did not finish.
- Renamed from Backup Center to **DevDriveBackup** for the public release. Start it with `DevDriveBackup.cmd`; the window, shortcut, icon and modules carry the new name. New recovery keys go to the "DevDriveBackup recovery keys" folder; an existing "Backup Center recovery keys" folder keeps being used and is still never copied. Re-create the desktop shortcut and re-pin the taskbar button once (`New-DevDriveBackupShortcut.ps1`).
- Keep deleted now finds every file gone from the source. robocopy's multi-threaded listing can put a record's path on the next line or start a line with the previous record's path; those files were not recognised, so they stayed in the plain copy and were never moved aside (282 of about 20,000 in one real run). `Get-RoboExtraPaths` reads every field of the listing, and a path that still exists in the source is never moved, checked again just before each move. Tested in `Test-BackupCopyRules.ps1`.
- The window has its own taskbar button with the DevDriveBackup icon instead of PowerShell's, and a pinned button starts DevDriveBackup again (`Backup.Taskbar.cs`).
- **Keep versions** on the overview: after each versioned backup, keep one version a day for N days, a week for N weeks and a month for N months, and delete older versions (`Backup-Worker.ps1 -KeepDays -KeepWeeks -KeepMonths`). The windows count back from the newest version, so a long pause never empties the history. restic plans it as a dry run; `Get-RetentionRemovals` refuses a plan that drops the version just made or every version of a folder set, keeps the newest version of each set protected, and the versions are then deleted by exact ID, their space freed with `prune` and the repository checked again. Only this tool's versions (tag `devdrive`) are considered. A failed clean-up is reported on the finished backup, never turned into a failed backup. Default: every version kept. Tested by `Test-BackupRetention.ps1` against a disposable repository with versions over 200 days.
- **Look** page: themes Light, Dark, Sand, Ocean and High contrast, and *Custom* from four chosen colours (window background, panels, text, main buttons) with secondary text, lines, selection and button text derived to stay readable. Every built-in theme passes WCAG 2.2 contrast for all text the window draws; for a custom theme the page names any pair below the minimum. Dark themes also use Windows' dark title bar, scroll bars and .NET's dark drawing of number boxes and drop-downs. The choice is saved in `%LOCALAPPDATA%\DevDriveMirror\center\appearance.json`. Colour logic in `DevDriveBackup.Theme.psm1`, tested by `Test-BackupTheme.ps1`.
- The window scales: a larger or maximised window enlarges every position, size and font by the same factor and centres the result; the smallest size is the original 1200 x 800.
- New program icon: the drive label with its status stripe, redrawn as vector with a separate small-size drawing for 16 to 24 px and a light rim that keeps it visible on dark taskbars. Sources, the three routes considered and their contact sheets are in `design/icon`; `New-DevDriveBackupIcon.ps1` draws the icon from those sources (it still drew the 0.1.0 icon).
- The light theme's secondary text is a little darker (#56636A), so it reaches 4.5:1 on a selected row too (was 4.31:1).
- The speed page no longer hides "No speed test yet..." behind the empty result labels. Disabled buttons stay readable on dark themes. The page tabs are text, not buttons.
- Opening the window lists the drives once instead of three times.
- **Waits for AI sessions**: *Back up now* and *Back up selected source* first check whether Claude Code or Codex sessions worked in the last 10 minutes, judged by their conversation files (`~/.claude/projects`, `~/.codex/sessions`) and running Codex programs, because the app's "running" flag and the list of open programs proved unreliable. If any did, the window names them and offers to wait: it checks every 30 seconds and starts the backup by itself after 10 quiet minutes. *Stop* cancels the wait. `Get-CenterAgentActivity`, tested by `Test-BackupActivity.ps1`.
- **Keep deleted for N backups** on the overview: each plain copy moves files deleted from the source out of the copy into a dated recovery folder beside it and keeps only the newest N recovery folders (`Invoke-FastMirror.ps1 -MoveExtras -KeepRecovery N`). 0, the default, keeps the old behaviour: deleted files stay in the copy. Nothing is moved aside after a run in which robocopy failed.
- **Drive check** page: checks the backup drive in four layers, each with its own verdict. *Quick check* reads the drive's health report (smartctl) and runs its short self-test, reads samples at the start, middle and end, looks for disk, reset and disconnection entries of the last 30 days in the Windows log (matched to this drive through Windows' record of drive arrivals, since disk numbers move between drives), checks the link speed and runs Windows' online file system scan. *Full surface scan* reads the whole disk, notes unreadable and suspiciously slow places, keeps the computer awake, and continues where it stopped. *Long self-test* starts the drive's own full read. Read only; runs as administrator (`Invoke-DriveCheck.ps1`), stopped through a request file because the window cannot end an elevated process.
- `Install-DriveTools.ps1` (and **Install health tool**) downloads smartmontools 7.5 with a pinned SHA-256 and installs only `smartctl` and its drive database into `bin\smartmontools`.
- `Test-PrivacyGuard.ps1` blocks private backup details (volume identifiers, profile paths, personal email, drive models and labels, folder names from your `*.local.json`) from commits, commit messages and pushes; hooks in `.githooks`, also run in CI.
- Plain copy no longer stops after copying when robocopy writes two "extra" records on one line during multi-threaded listing.
- Plain copy and versions never copy DevDriveBackup's own folders of passwords, recovery keys and state, even when the source holds them (for example a whole user folder or drive). Before, a plain copy could put the readable recovery keys on the backup drive.
- *Check backup content* now also finds files that are missing from the plain copy, not only files that differ. It no longer creates an empty copy folder, and it no longer counts as a completed backup.
- Plain copy refuses to run when the drive letter now belongs to a different drive than the profile's backup drive.
- A folder inside a *NeverBackUp* folder is never backed up, even if it is marked for backup itself.
- A selected folder that is missing or became a link now fails the plain copy with its name, instead of being skipped quietly.
- A folder in the source where the copy has a file of the same name (or the reverse) now counts as a copy error instead of passing unnoticed.
- Two sources never share one plain copy folder: a new source never reuses a copy folder already on the drive, and a folder added again keeps its own. Adding two folders with the same name no longer freezes the window.
- A source with no subfolders can now be backed up and checked as a plain copy.
- The first full check of a plain copy is remembered per drive rather than per drive letter, so a new drive with the same letter is checked in full. Each existing plain copy gets one full check after this update.
- The content check skips the folders and names the copy skips, so a folder excluded later no longer shows up as a difference.
- Saving a source's settings waits for, and never overwrites, a password change in progress; if a backup of that source is running, it says so instead.
- **Install health tool** and **Long self-test** now see an installed smartctl (a stray character in its path made the window think it was missing).
- A load level changed during a run now applies to the next step, threads, priority and versions settings alike; the running step's priority changes at once. A step that cannot start or whose result cannot be recorded is reported as failed instead of leaving the run stuck. Step logs no longer overwrite each other. *Back up selected source* prepares only that source.
- Closing the window asks about a running backup and a running drive check first, and stops nothing unless it really closes. A drive check cannot start while an earlier one (also from a closed window) still runs, and its stop request is kept. A profile that is being checked or speed-tested cannot be removed.

- The documentation matches the code again: BACKUP-SYSTEM.md describes the automatic clean-up of old versions, the main window's load levels, the real button names and the drive check thresholds, and the README lists every program, test and document file. The checks on every push also build `Backup.Taskbar.cs`, run `Test-BackupResourceControls.ps1` and use `actions/checkout@v7`. Two tests no longer leave an empty folder in `%TEMP%` after each run.

## 0.1.0 — first public release

### Backup Center window
- One profile per backup drive, recognised by volume identity, each with its own sources.
- Any folder or drive as a source; per-folder modes Plain copy, Versions, Both or Skip, shared by both engines.
- Age of the last complete backup with colour states against a "Mark as old after" period; no scheduler or reminder by design.
- Computer load levels (Light, Balanced, Strong, Maximum, Custom) computed from the detected processor and memory; priority can be changed while a backup runs.
- Back up, back up one source, check backup content, stop, open the plain copy, versions and restore, password and recovery key.
- Drive speed test without freezing the window, recent runs with duration and average speed, explanations on every page.
- Unexpected errors are shown in plain words and logged to `%LOCALAPPDATA%\DevDriveMirror\center\ui-errors.log`.

### Plain copy (`Invoke-FastMirror.ps1`)
- robocopy-based incremental copy with parallel files, junction/link skipping and cache skipping.
- Locked files are counted and reported without stopping the run; totals are read in any Windows language.
- Files only in the copy are reported and, on request, moved to a dated recovery folder; never deleted.
- `-Verify` compares SHA-256 of every copied file; `-VerifyOnly` checks without copying. Files that exist only in the copy are reported separately from content differences.
- Refuses the source's own disk and the disk holding a Dev Drive VHDX, and a source drive whose volume identity changed.
- Personal skips from the configuration's `Exclude` (names and paths) and `NeverBackUp`.

### Versions (`Backup-Worker.ps1`, restic 0.19.1)
- Encrypted, deduplicated snapshots with DPAPI-protected password, portable recovery key, hard memory cap, CPU and I/O limits, and `restic check` after every backup.
- A folder selected inside a skipped folder is included (restic would otherwise drop it).
- Only a backup creates a repository; history and checks report a missing repository instead of creating an empty one.
- Restore below protected folders succeeds with a warning when only parent-folder timestamps cannot be set.
- Recovery keys default to a local, unsynced folder in the user profile.
- History browsing, selective restore, deletion with typed confirmation and optional prune, and resumable password changes.

### Tools
- `Set-BackupDestination.ps1` and `Measure-BackupDisk.ps1`: drive model, health, file system, USB link speed and benchmark.
- `New-BackupCenterIcon.ps1`, `New-BackupCenterShortcut.ps1`: program icon and desktop shortcut.
- Launchers check for PowerShell 7.2+ and show problems instead of failing silently.
